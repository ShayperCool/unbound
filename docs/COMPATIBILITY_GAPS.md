# Compatibility gap map (Unity 6000.0.71f1)

What Unbound does not yet do as the Editor does, found by auditing the engine itself rather than
waiting for a game to hit it. `ROADMAP.md` says what is done and probed; this file lists what is
left, ranked, so work can go down it.

Audit of 2026-10-29: read-only, every subsystem; nothing was measured against the Editor, so each
row still needs a probe before and after it is fixed. Paths are relative to `managed/UnityEngine/`
unless they start with `crates/` or `native/`.

## Known insignificant residuals

By the user's decision of 2026-11-01, small differences with no visible effect or
game-logic change do not block package admission. Raw values and comparator
tolerances stay unchanged; strict verifiers still report these failures.
Roughly 1-3/255 in isolated pixels is an example, not a blanket tolerance.
Visible or functional systematic biases, wrong functional answers, changes in
survival, death/event timing or ordering, and actual bugs remain actionable.
A numeric lifetime-field difference alone does not establish a functional change;
its effect on the measured histories still matters. No Native captures or deep research are spent solely
to eliminate a listed insignificant residual.

## How gaps hide

Game runs keep hitting features that are missing *without a warning* (physical cameras,
`Camera.SetReplacementShader`). The generated stubs warn on first use; these do not:

| Pattern | Example | Why it is silent |
|---|---|---|
| Hand-written empty body | `Camera.SetReplacementShader { }`, `Animator.ApplyBuiltinRootMotion` | A hand-written member suppresses the generated stub, and with it the warning (516 empty public bodies in the hand-written sources, many legitimate) |
| Stored, never consumed | `Physics2D.simulationLayers` | Auto-properties and fields the frame/simulation never reads |
| Serialized field or import setting not read | `m_DisabledShaderPasses`, `m_RenderingPath`, terrain lightmap, ModelImporter clip masks/root motion, `m_ContactPairsMode` | `ReadSerialized` / the importers read a subset of keys and drop the rest |
| Message looked up, never sent | `OnParticleUpdateJobScheduled` (`Messages.cs` `s_NotSent` lists them) | Messages are not API calls: `api-gaps` cannot see them |
| Overload drops a parameter | `Graphics.ConvertTexture(src, srcElement, dst, dstElement)`, `Mesh.Set*(..., flags)`, stereo-eye overloads (Blit slices, `LogOption`, `SetPropertyBlock` index done) | Forwarded to the simpler overload |
| Asset class with a ClassId but no reader | done (`classids`): a class without a reader warns once at load, naming the class and the file, and `unbound doctor` lists the project's files holding one | Ignored classes (`ClassCoverage.s_Ignored`, with a reason) stay silent |
| Stub default not neutral | done (`stubdefaults`): value-returning stubs take the Editor's answer from `StubDefaults.cs` where it is a constant; `ScalableBufferManager` and `CalculateObliqueMatrix` are hand-written, `Microphone.devices` takes the generator's empty-array rule | Members whose answer is not a constant still return the default after their warning (see the tooling item) |
| Generated stub events | done: subscribing warns that the event is never raised | |
| Claimed capability | `SystemInfo.supportsTextureWrapMirrorOnce` (MirrorOnce samples as Mirror; `supports3DRenderTextures` now answers false) | Packages enable a path that then draws nothing |
| Warn once, then silent | SpriteMask, reflection probes | A second scene shows nothing in the log |

## Tooling first: make every gap loud

Each of these turns a class of silent gaps into a list that keeps itself up to date:

- [x] `Stubs.Ignored(member)` (warn once, like `NotImplemented`) for knowingly ignored members,
      and an `[EditorFaithful("why")]` marker for real no-ops; every hand-written empty body,
      constant answer, dropped setter and never-raised event carries one of the two (or is
      implemented). `unbound api-check` fails (category `silent`) on any that carries neither.
- [x] Stub generator: events warn on `add`; value-returning stubs take the Editor's answer from a
      small table where 0/null is wrong (`managed/Unbound.ApiTools/StubDefaults.cs`, measured by
      `stubdefaults`; gen-stubs fails on stale entries or expression type mismatches). Still returning the
      default because the answer needs a real implementation: `UnityEngine.Device.Screen`/
      `Application`/`SystemInfo` (forward to the non-Device classes in the Editor),
      `GarbageCollector.isIncremental` (player setting), `Caching` (`cacheCount` 1 and
      `defaultCache`), the `QualitySettings` terrain and texture streaming settings, `Physics2D.jobOptions`
      and `GraphicsSettings` asset values, `Time.captureDeltaTimeRational`, serialized component
