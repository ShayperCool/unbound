# Runtime material memory

The Unity 6000.0 Scripting API describes `Profiler.GetRuntimeMemorySizeLong` as the target object's native memory use and documents zero when the profiler is unavailable. ShaderLab declares a material's serialized properties and distinguishes an `Integer` from the legacy float-backed `Int`. `Material.SetFloat` writes a named float, and `Material(Material)` creates a copy of a material. `Object.Instantiate` clones the supplied object, and `Material.HasProperty` checks its shader for the named property. The API leaves the allocation sizes, capacity growth and copy reservations unspecified. [Profiler API](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Profiling.Profiler.GetRuntimeMemorySizeLong.html), [ShaderLab Properties](https://docs.unity3d.com/6000.0/Documentation/Manual/SL-Properties.html), [SetFloat](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Material.SetFloat.html), [Material constructors](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Material-ctor.html), [Instantiate](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Object.Instantiate.html), [HasProperty](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Material.HasProperty.html)

Two independent 6000.0.71f1 Editor runs agree on each of Metal, OpenGL Core and Vulkan. The fixture uses nine shader declaration layouts plus the built-in Standard and Unlit/Color shaders. It reports the declaration types, cold native sizes, declared property edits, render queue and instancing changes, ten distinct appended floats, a repeated name and separately edited constructor and `Object.Instantiate` copies. The mix includes float-compatible ranges, true integers, colors, vectors and several texture dimensions. A constructor copy reports the shader's initial size even when the source has grown. `Object.Instantiate` begins with the object header alone. Reading shader metadata and changing the render queue leave that allocation unchanged. Querying a property or reading its value builds the declared property storage. A subsequent edit of either copy leaves the source's size unchanged.

An initialized plain runtime material starts at 1,832 bytes on Metal and 2,072 bytes on the measured Linux devices. An instantiated object begins with 416 fewer bytes until its property storage is initialized. One float, range or integer declares one key and one value word. A color or vector uses one key and four words. A texture uses four keys and 21 words. A key costs 12 bytes and a word costs four bytes. The total includes live entries and their reserved slots. Initially the reserved counts equal the declarations. An extra float uses one key and one word. The key reserve doubles from its initial count when full, starting at one for an empty store. Value words reserve exactly the live count for float and range layouts and double when full for layouts with integers, colors, vectors or textures.

The model covers explicit, complete top-level declarations from imported project ShaderLab source or available built-in shader source on the measured devices and release family. Materials with keywords active at creation remain outside this scope. The observations describe profiler accounting. They leave existing Material values and rendering behavior as they were. Asset materials, variants, incomplete or synthesized layouts, texture-companion name collisions, synthetic draw materials, shader replacement, property group copies, non-scalar additions, texture sub-elements and edits to keywords, tags or pass state remain outside the measured scope. A pending copy prepared for drawing has an unmeasured intermediate allocation until a property API builds its ordinary storage. Material size returns the existing warned zero outside this scope.
